## 0. Status & Scope

v1 is complete. Live at `guivutru.pages.dev`. Dark-mode only. Local-first (localStorage, no backend). Real-device matrix pending, otherwise shipped.

v2 introduces a backend, accounts, and the public wish wall ("Bầu trời điều ước") that the landing page has been promising since v1. It also deepens the private product with voice notes, reminders, and time-capsule formats.

v2 is **not one release**. It is three sub-releases that must ship in order.

---

## 1. Strategic Fork — Pick One

The product can evolve two mutually exclusive ways. Doing both at once will produce a mediocre version of each.

### Path A — Social Cosmos

Notes can be public. A wall of anonymous stars. Browse, tap, read. Cross-device sync via accounts.

**Pros:** Activates the "sắp mở" promise. Shareable. Grows by word-of-mouth. On-brand.

**Cons:** Requires backend, moderation, rate limiting, and a legal stance on user-generated content in Vietnam.

### Path B — Private Time-Capsule

No public wall. Cross-device sync, reminders, richer private features (voice notes, collections, unlock rituals). Stays a personal journaling tool.

**Pros:** No moderation burden. Smaller surface. Deeper emotional product.

**Cons:** Caps growth. Word-of-mouth only. The "sắp mở" link stays dark forever and becomes a broken promise.

### Recommendation

**Path A, built in strict order: backend first, wall second, moderation baked in from day one.**

The landing page links to a public wall. That is a promise to users. Honoring it is the product's natural second act.

**This decision must be confirmed in §12 before any code is written.**

## 2. v2.0 — "Đám mây" (Cloud)

Foundation. Nothing user-facing except sync and a login button.

**Estimated effort:** 3–4 weeks solo.

### 2.1 Backend

- **Supabase project** — Postgres + Auth + Row-Level Security.
- Recommended over Cloudflare D1 + Workers for v2.0 because auth, email, and RLS come out-of-the-box. Revisit D1 only if vendor lock-in becomes a concern later.

### 2.2 Authentication

- **Magic link only.** No passwords, no OAuth. Email → click → signed in.
- Vietnamese copy:
  - Entry: `Đăng nhập để đồng bộ`
  - Sent: `Mở email để đăng nhập nha 📬`
  - Success: `Đã đăng nhập ✨`
  - Error: `Link hết hạn rồi, gửi lại nha`

### 2.3 Data Schema

```sql
-- Table: notes
id              text primary key         -- server-generated id
user_id         uuid references auth.users not null
device_id       text                     -- for local-first merge
content         text                     -- encrypted at rest, but see 2.4
prompt_id       text
paper_theme     text                     -- 'dem-sao' | 'tim-mong' | ...
sticker_ids     text[]
unlock_at       timestamptz
status          text                     -- 'sealed' | 'opened'
visibility      text                     -- 'private' | 'public' (v2.1)
created_at      timestamptz
opened_at       timestamptz
updated_at      timestamptz
is_deleted      boolean default false    -- soft delete
```

### 2.4 Security — the load-bearing rule

**RLS policy must return `null` for `content` when `status = 'sealed'` and `unlock_at > now()`, regardless of who is asking.** Not even the owner's own client can read sealed content until unlock. This is the product's core privacy promise and must survive the backend migration.

Sealed content is:

- Stored encrypted at rest in Postgres (Supabase encrypts by default)
- Returned as `null` from any query where the seal hasn't expired
- Rendered client-side only after a signed fetch at unlock time

### 2.5 Sync

- **Local-first, cloud-synced.** The app must work fully offline with no account, exactly as v1.
- On login:
  - Notes in localStorage are uploaded if not already on server
  - Server notes not on device are downloaded
  - Conflict resolution: server wins on `updated_at`, EXCEPT for local notes with no `server_id` (those are new, upload them)
- On logout: cloud notes are removed from localStorage; local-only notes stay.
- **No sync without login.** Never silently upload.

### 2.6 Account UI

- One button in TopBar: user avatar circle (empty state: outline; logged in: first letter of email).
- Clicking opens a small menu:
  - `Góc của tôi` → `/toi`
  - `Đăng xuất`
  - (if not logged in) `Đăng nhập để đồng bộ`
- No settings page in v2.0.

### 2.7 Acceptance

- Signed-in user sees the same notes on two devices.
- Signed-out user still has a fully working local app.
- A sealed note's content is not fetchable via the API, even by its owner, before unlock.
- No localStorage data leaves the device without explicit login.

## 3. v2.1 — "Bầu trời" (Sky)

The public wall. The "sắp mở" link activates here.

**Estimated effort:** 4–6 weeks solo, gated on moderation design.

### 3.1 Publish Toggle

On `/viet` Step 3, the current privacy radio becomes functional:

- ● `Chỉ mình mình` (default)
- ○ `Ẩn danh trên bầu trời`

Selecting the second option adds a small confirmation panel:

> _"Điều ước này sẽ xuất hiện trên Bầu trời điều ước sau khi mở. Không ai biết là của bạn. Bạn có thể xoá bất cứ lúc nào."_

### 3.2 `/bau-troi` Route

- Canvas of anonymous stars, one per public note.
- Star position deterministic from `note.id` (same hash function as `ConstellationView`).
- Star brightness by note age; new notes glow brighter for the first 24h, then settle.
- Tap a star → modal with note content. Content only shown if `status = 'opened'` or `unlock_at <= now()`. Sealed public notes show only _"Điều ước này chưa đến ngày mở 🔒"_.
- Filter bar: `Mới nhất` / `Sắp mở` / `Ngẫu nhiên`.
- Empty state: curated seed of ~20 notes written by you, marked as `seed = true` in the DB.

### 3.3 Anonymous Identity

**Recommended: stable pseudonym per user.**

- Each user gets a random 2-word Vietnamese pseudonym on first public post (`mèo-lười-42`, `sao-băng-7`).
- Same user's public notes share a pseudonym, so their stars form a private constellation they can revisit at `/bau-troi/cua-toi`.
- No email, no name, no profile visible to other users.
- Rationale: 100% anonymous notes feel disconnected; a pseudonym gives users a "home" on the wall without real identity.

### 3.4 Moderation (non-negotiable)

Three layers:

1. **Pre-filter.** Vietnamese + English bad-word list on submit. Reject with `Viết lại nhẹ nhàng hơn nha, vũ trụ nghe hết á 🌙`. List lives in `functions/` as a static file so it can be updated without deploy.
2. **Report button.** Every public note has a small `Báo cáo` link. One report hides the note pending review.
3. **Admin queue.** Simple `/admin/bao-cao` route (auth-gated by email allowlist) listing reported notes with `Duyệt lại` / `Xoá` buttons.

### 3.5 Rate Limiting

- 1 public note per user per day.
- 5 public notes per user per week.
- Enforced server-side. Client shows: `Bạn đã gửi hôm nay rồi, mai quay lại nha 🌙`

### 3.6 What's NOT in v2.1

- No comments. No replies. No direct messages. Ever.
- No reactions yet (v2.2).
- No user profiles visible on the wall.
- No follower/following model.

### 3.7 Acceptance

- Any user can browse the wall without an account.
- Publishing requires login.
- Reported notes disappear within 1 minute of report.
- Bad-word filter blocks the obvious cases.
- Rate limit triggers correctly.
- Zero PII on public notes.

## 4. v2.2 — "Nhắc nhở & Nhà" (Reminders & Home)

Retention features built on the cloud foundation.

**Estimated effort:** 3 weeks solo.

### 4.1 Email Reminders

- Provider: **Resend** (simplest API, cheapest at this scale).
- One email per note, on the day `unlock_at` passes.
- Vietnamese copy: _"Bạn của ngày xưa gửi cho bạn một lá thư…"_ — same line as the unlock ritual.
- Unsubscribe link required by law. Single toggle in account menu.
- No digests, no marketing emails, ever.

### 4.2 Zalo OA Reminders (Vietnam-specific)

- Zalo Official Account, approved via Zalo Business.
- Same trigger as email, different channel.
- **Important:** Zalo OA requires business verification and approval. Start this process at the _beginning_ of v2.2, not the end.
- If approval is denied or delayed, ship email-only and add Zalo in a patch.

### 4.3 PWA

- `manifest.webmanifest` with icon set, theme color, display: standalone
- Install prompt on second visit
- Offline read for `/toi` and `/note/:id` via service worker cache
- Do NOT cache `/viet` submission — offline write is a v3 concern

### 4.4 Reactions on Public Notes

- Three options only: 🌙, ⭐, 💗
- One reaction per user per note. Changeable.
- No counts shown to the note author unless >10.
- Rationale: reactions must not turn wishes into content for engagement.

### 4.5 Year in Review

- On the anniversary of a user's first note, generate a shareable card:
  - "Năm đầu tiên gửi vũ trụ" or similar
  - Stats: notes written, words sent, moons watched
  - One note selected as "điều ước của năm"
- Share card uses the v1 `ShareCard` system, new template.
- Optional: only if the user has ≥5 notes.

### 4.6 Acceptance

- Reminder email arrives on the correct day, in local time.
- PWA installs on iOS and Android.
- Offline `/toi` shows cached notes.
- Reactions persist across devices.
- Year-in-review card renders correctly and exports.

## 7. Locked Constraints (v2 amendments)

Inherited from v1 `HANDOFF.md` §2 and `AGENTS.md`, with the following amendments:

1. **Dark mode only.** Light mode was removed in v1. Do not reintroduce.
2. **Reduced-motion must be respected on every animation.** No exceptions, including the new public wall.
3. **v1 core still works without an account.** The local-first path is not deprecated.
4. **Sealed content is never returned from the server** to any client, including the owner, before `unlock_at`. Enforced by RLS, verified by tests.
5. **No PII on public notes.** No email, no name, no IP stored alongside content.
6. **No user content is ever used for training, analytics, or third-party services.**
7. **All API calls go to Supabase only.** No third-party analytics, no tracking pixels, no Google services.
8. **Rate limits are enforced server-side.** Client-side is a courtesy, not the guard.
9. **Public features require login. Browsing does not.**
10. **Every v2 feature ships with an RLS policy and a test.**

## 8. Risks

| Risk                              | Likelihood | Impact   | Mitigation                                                                                        |
| --------------------------------- | ---------- | -------- | ------------------------------------------------------------------------------------------------- |
| Moderation fails at scale         | Medium     | High     | Rate limit hard, report button prominent, admin queue reviewed daily for first month              |
| Legal exposure on UGC in Vietnam  | Medium     | High     | Consult a Vietnamese lawyer before shipping v2.1. Budget 5–10M VND.                               |
| Zalo OA approval denied           | Medium     | Medium   | Ship email-only, add Zalo later                                                                   |
| Supabase costs spiral             | Low        | Medium   | Free tier handles ~10k MAU. Monitor.                                                              |
| Local-first sync bugs (data loss) | Medium     | High     | Never overwrite local notes with cloud on login. Only merge. Test with 0-note and 100-note cases. |
| Auth friction kills conversion    | Medium     | Medium   | Login is optional. Local-only path remains first-class.                                           |
| Sealed content leaks via API      | Low        | Critical | RLS test in CI. Never trust the client.                                                           |
